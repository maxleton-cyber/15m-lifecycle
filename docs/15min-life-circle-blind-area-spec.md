## 2. 数据模型

```text
Facility(设施)
  id, category, name
  access_points[]        // 可进入/到达的点位(出入口、站点等),至少1个
  raw_category, raw_id   // 原始分类与原始POI id,便于追溯

Cell(网格)
  id, polygon, origin_point
  state                  // valid | invalid(非步行区域)
  covered[category]      // 各类别是否有可达设施
  missing_set            // 缺失的类别集合
  missing_count          // 缺失类别数
  level                  // 灰度级别 = missing_count
  degraded               // 是否含降级估算结果
```

**关键设计:一个设施可以有多个接入点。** 地铁站有多个出入口,公园有多个大门,公交站有上下行站牌。统一建模为"1个设施 + 多个接入点",可达性取各接入点中步行距离最小的一个。这样去重和计数不会互相冲突。

## 3. 配置项总览

```yaml
grid:
  size_m: 100                 # 网格边长
  min_inside_ratio: 0.5       # 格子与等时圈相交面积占比低于此值则丢弃

reach:
  default_threshold_m: 1000   # 默认可达阈值(步行距离)
  by_category:                # 按类别单独配置;未配置的类别使用默认值
    基础医疗: 1000
    药店: 1000
    学校: 1000
    购物: 1000
    养老服务: 1000
    公园绿地: 1000
    公共交通:                 # 子类型可分别配置;任一子类型可达即覆盖
      公交站: 1000
      地铁站: 1000

origin:
  snap_max_m: 150             # 起点距路网超过此值 → 非步行区域

prune:
  top_k_candidates: 3         # 每格每类最多计算的候选设施数

fallback:
  retry: 3                    # 失败重试次数(指数退避)
  detour_factor: 1.3          # 降级估算:直线距离 × 绕行系数

facility:
  snap_max_m: 150             # 设施接入点距路网超过此值 → 可达性存疑

blind:
  min_area_m2: 0              # 盲区碎片最小面积,0 表示不过滤
```

> 以上默认值中,所有类别的 R 起始均为 1000 m,与"可达阈值按1000m"的决策保持一致。各类别如需调整,只改 `by_category`,代码不改。

下表是常见生活圈步行半径习惯下的**参考调整范围**,不是赛题或官方标准,字幕中也没有提到,采用前请自行核实。

| 类别 | 当前默认 R | 可选调整参考 |
|---|---|---|
| 基础医疗 | 1000 m | 保持 |
| 药店 | 1000 m | 可收紧到 500~800 m |
| 学校(小学) | 1000 m | 保持,或 800 m |
| 购物(菜市场/超市/便利店) | 1000 m | 可收紧到 500~800 m |
| 养老服务 | 1000 m | 保持 |

## 4. 类别清洗

### 4.1 七类定义

| 类别 | 纳入 | 排除 |
|---|---|---|
| 基础医疗 | 社区卫生服务中心/站、乡镇卫生院、综合医院、门诊部、诊所,**含口腔、中医、妇幼等专科** | 宠物医院、医美/整形、纯体检机构、医疗器械店、药店(单独成类)、院内子点 |
| 药店 | 连锁药房、社区药店 | 批发、器械店、保健品店、院内药房 |
| 学校 | **小学**(含附属小学) | 幼儿园、初中、高中、大学、培训/早教机构、校内食堂/宿舍/操场等子点 |
| 购物 | **菜市场/农贸市场、超市、便利店** | 商场内专卖店、批发市场、服饰/数码/烟酒专卖、自提点 |
| 养老服务 | 养老院/敬老院、社区养老服务中心、日间照料中心、老年活动中心、养老驿站 | 殡葬、墓园、保健品销售、养老社区售楼处 |
| 公园绿地 | 公园、街心/口袋公园、对公众开放的广场绿地 | 小区内部绿化、道路绿化带、封闭景区、收费游乐园、墓园 |
| 公共交通 | **公交站、地铁站** | 停车场、长途客运站、已停运站点 |

**易混淆处理**

| 易混淆 | 处理方式 |
|---|---|
| 药店 与 基础医疗 | 药店单独成类;基础医疗中剔除药店;医院内药房不单独算药店 |
| 购物 与 药店 | 药店不计入购物;超市内的药品柜不单独计 |
| 学校 与 培训机构 | 培训机构一律不算学校 |
| 公园 与 小区绿化 | 以分类标签为准,名称仅作辅助校验 |
| 养老 与 医疗 | 带护理床位的养老机构归养老,不重复计入医疗 |

### 4.2 清洗流水线

每一步都要写**清洗日志**:被剔除或改类的POI、原因、规则编号。

**P0 检索**
- 每个类别用「分类标签检索 ∪ 关键词检索」取并集,提高召回。
- 一个类别拆成多个子查询(如养老:养老院、日间照料、老年活动中心)。
- 检索范围按网格或分片切分,并处理分页,避免因单次返回上限漏数据。
- 检索范围取等时圈外包一圈缓冲,缓冲距离不小于所有类别 R 中的最大值,因为圈边缘的格子要用到圈外的设施。

**P1 标准化**
- 统一字段结构与坐标系。
- 名称去空格、全半角统一、去除无意义的括号后缀。

**P2 分类映射**
- 原始分类标签映射到本项目的7个类别,映射表写成配置。
- 一个POI只归一个类别;多标签冲突时,"排除规则优先",再按优先级表裁决。

**P3 名称规则校验**
- 命中**黑名单**关键词 → 剔除。
- 标签属于某类别,但名称命中其他类别强特征(如标签为医疗、名称含"宠物") → 剔除。
- 命中白名单关键词但标签不符 → 进入"待复核",不自动纳入。
- 公园绿地不能仅凭名称含"花园"判断(楼盘常叫"XX花园"),以分类标签为准。

**P4 子点剔除**
- 名称形如 `主体-子点`、`主体(子点)`,且子点是"挂号处、食堂、东门、药房"等内部设施 → 并入主体,不单独计数。

**P5 同类去重与聚合**(核心算法)

```text
对每个类别内的POI:
  1. 名称规范化后分组
  2. 组内按空间距离聚类(阈值 d_c,见下表)
  3. 同一聚类合并为一个 Facility:
       位置取聚类代表点
       所有原始点位保留为 access_points
```

| 类别 | 同名合并距离 d_c(建议) | 说明 |
|---|---|---|
| 基础医疗 | 50 m | 同院区多个入口合并 |
| 药店 | 20 m | 连锁药店可能相邻,距离要小 |
| 学校 | 100 m | 同校区多个门合并;**不同校区不合并** |
| 购物 | 20 m | 连锁便利店可能相邻 |
| 养老服务 | 50 m | |
| 公园绿地 | 300 m | 大公园多个大门 |
| 公共交通 | 公交站按站名合并 80 m;地铁站按站名合并,所有出入口作为接入点 | 上下行、多出口合并为一个设施 |

**P6 范围与坐标校验**
- 剔除坐标缺失、明显越界或落在水面等不合理位置的点。
- 仅保留位于「等时圈 + 缓冲」范围内的点。

**P7 接入点吸附**
- 每个接入点吸附到最近的可通行路网点。
- 吸附距离大于 `facility.snap_max_m` 的接入点标记为"可达性存疑",默认不参与可达判定(可配置)。

**P8 输出**
- 清洗后设施表,同时保留原始分类和清洗后分类两个字段。
- 清洗日志与统计:各规则剔除数量、各类别清洗前后数量。

### 4.3 清洗质量评估

1. 每类随机抽 30~50 个清洗后设施,人工判断是否属于该类别,计算**精确率**。
2. 选一个熟悉的社区,人工列出真实设施清单,对照系统结果计算**召回率**。
3. 数据与结论写入技术设计文档(★ 技术文档要求讲清POI数据清洗)。
4. 总体策略:**检索从宽、准入从严**。把非设施当设施会使盲区漏报,漏掉真实设施会使盲区误报,两类错误方向相反,需在文档中说明取舍。

## 5. 盲区判定与标注

### 5.1 判定口径

> 对网格 g 和类别 c:若**存在**该类别的某个设施 f,使得从 g 的起点步行到 f 任一接入点的**路网步行距离 ≤ R_c**,则 g 对类别 c **已覆盖**;否则 g **缺失**类别 c。

- R_c 为该类别的可达阈值,取自 `reach.by_category`,基准为 1000 m。
- **公共交通**:公交站可达(≤ R_公交站)或地铁站可达(≤ R_地铁站),任一成立即视为已覆盖。
- 判定一律基于路网步行距离(★ 真实可达),不使用直线距离。

### 5.2 算法

**步骤 1:生成网格**

```text
bbox = 等时圈多边形外包框
边长 G(默认100 m)的正方形网格铺满 bbox
对每个格子:
  inter = 格子 ∩ 等时圈
  若 area(inter) / area(格子) < min_inside_ratio → 丢弃(圈边缘碎格)
  否则 起点候选 = 格子中心;若中心不在圈内,取 inter 的重心
```

**步骤 2:起点吸附与有效性判定**

```text
起点吸附到最近可通行路网点
若 吸附距离 > origin.snap_max_m → cell.state = invalid(非步行区域)
否则 cell.state = valid
```

- invalid 格子**不参与盲区判定**,也不计入各项指标的分母,但需要在地图上用斜线纹理标示(见 5.4)。
- 风险提示:封闭小区内部可能距离城市道路较远。若 `snap_max_m` 设得过小,居民区可能被误判为非步行区域,从而隐藏真实盲区。请在真实社区上实测,并相应调整该阈值。

**步骤 3:候选设施剪枝**(降低API调用量的关键)

```text
直线距离 ≤ 步行距离(恒成立)
→ 若 直线距离(g, f) > R_c,则 f 一定不可达,无需算路

for each valid cell g:
  for each category c:
    candidates = 直线距离(g, f) ≤ R_c 的设施,按直线距离升序,取前 K 个
    若 candidates 为空 → covered[c] = false(不调用API)
```

此剪枝是**严格安全**的,不会漏判。公共交通按子类型分别用各自的 R 剪枝。

**步骤 4:步行距离计算**

```text
对每个候选设施:
  步行距离 d = 步行路径规划结果(取该设施各接入点中的最小值)
按直线距离升序判断:一旦 d ≤ R_c → covered[c] = true,停止该类别
所有候选都 > R_c → covered[c] = false
```

- 优先使用批量算路接口;控制并发与请求速率(★ 并发与限速评估)。
- 结果缓存,键为 `起点格子id + 设施id`,重复运行不重复请求。

**步骤 5:容错降级**

```text
API 失败 → 指数退避重试,最多 retry 次
仍失败 → 步行距离 ≈ 直线距离 × detour_factor,并标记 cell.degraded = true
```

结果中统计降级格子比例,并在界面或文档说明,避免结果可信度受质疑(★ 容错降级是评分点)。

**步骤 6:计算缺失与级别**

```text
cell.missing_set   = { c | covered[c] == false }
cell.missing_count = |missing_set|
cell.level         = missing_count        // 范围 0~7
```

**步骤 7:合并成盲区块**

```text
仅 state = valid 且 level ≥ 1 的格子参与
按 level 分组,同 level 且相邻的格子 union(dissolve)成多边形
与等时圈做 intersection,保证不超出圈外
面积小于 blind.min_area_m2 的碎片按配置过滤
```

后端若使用 C#,可用 NetTopologySuite 做 union 和 intersection;前端可用 turf.js。

### 5.3 盲区样式:透明灰、逐级加深

色值为灰色,每缺一类加一级,**透明度始终小于不透明**,上限 0.65。

| 缺失类别数 | 灰度值 | 透明度 α | 填充 |
|---|---|---|---|
| 1 | 160 | 0.15 | `rgba(160,160,160,0.15)` |
| 2 | 148 | 0.22 | `rgba(148,148,148,0.22)` |
| 3 | 136 | 0.29 | `rgba(136,136,136,0.29)` |
| 4 | 124 | 0.36 | `rgba(124,124,124,0.36)` |
| 5 | 112 | 0.43 | `rgba(112,112,112,0.43)` |
| 6 | 100 | 0.50 | `rgba(100,100,100,0.50)` |
| 7 | 88 | 0.57 | `rgba(88,88,88,0.57)` |

- 公式:`α(n) = 0.15 + 0.07·(n−1)`;`gray(n) = 160 − 12·(n−1)`;`α_max = 0.65`。
- level = 0 不绘制。
- 7 个级别肉眼区分较难,以上色阶是起点,**请在实际底图上看效果后微调**;同时调整灰度和透明度比只调一个更易区分。
- 盲区块加同色系 1 px 细描边,不用粗线。
- 等时圈本身建议只用描边加极淡填充(α ≤ 0.08),避免与灰色混成脏色。

### 5.4 非步行区域:斜线纹理

**定义**:`state = invalid` 的格子,即起点距离可通行路网过远(如水面、铁路用地、大型封闭区域),不参与盲区判定。

**标示规则**
- 用**斜线纹理**表示,图例名称为「非步行区域」。
- 纹理只用线条,**不使用灰色填充**,避免与盲区灰度梯度混淆。
- 建议样式:45° 斜线,线色 `rgba(120,120,120,0.45)`,线宽 1 px,间距约 6 px,无底色。
- 相邻 invalid 格子合并为多边形,并与等时圈做 intersection,不超出圈外。
- 悬浮或点击提示:「非步行区域:距可通行路网较远,不参与盲区判定」。
- 支持图层开关,可单独显示或隐藏。
- 非步行区域与盲区块**互不重叠**(invalid 格子不参与盲区判定)。

**实现提示**:多边形纹理填充是否被所用 SDK 直接支持需要实测。若不支持,备选方案包括:自定义图层 / Canvas pattern 绘制;或将斜线生成为裁剪后的折线集合叠加。请在实现前先验证。

### 5.5 图层顺序与交互

图层从下到上:

1. 底图
2. 等时圈
3. 非步行区域斜线层
4. 盲区灰色层
5. **设施点位**(必须在灰色层之上,否则被盖住)
6. 高亮与弹窗

**交互**
- 图例:盲区色块复用同一份色阶配置,标注"缺1类 … 缺7类";另含「非步行区域」斜线图例。
- 悬浮或点击盲区块,显示:缺失类别清单、面积、各缺失类别的最近设施及其步行距离(该距离可能大于 R_c)、是否含降级估算。灰度只表示"缺几类",**具体缺什么靠弹窗**。
- 图层开关:等时圈、设施点位、盲区、非步行区域,可单独显示或隐藏。
- 按类别筛选:只勾选部分类别时,`missing_count` 仅统计选中类别并重新着色。
- 降级格子:可用虚线描边或在弹窗中注明"含估算结果"。

### 5.6 指标与结论

**分母统一为「有效格面积」**(即 `state = valid` 的格子面积之和),非步行区域不计入。

| 指标 | 定义 |
|---|---|
| 各类覆盖率 | 该类别已覆盖的有效格面积 / 有效格总面积(按各类别自己的 R_c 判定) |
| 盲区面积占比 | `level ≥ 1` 的面积 / 有效格总面积 |
| 平均缺失数 | Σ(格面积 × missing_count) / 有效格总面积 |
| 盲区块清单 | 每块的 level、缺失类别、面积、位置 |
| 非步行区域占比 | invalid 面积 / 等时圈总面积 |
| 降级比例 | 降级格子面积占有效格总面积 |

**文字结论**由规则自动生成,例如:覆盖率最低的类别,以及最严重盲区块的位置与缺失类别。

**图表**(★):柱状图展示各类覆盖率,雷达图展示综合水平。

## 6. 整体流程

```text
1  读取等时圈与中心点
2  检索设施(含缓冲)→ 清洗 P0~P8 → 设施表
3  生成网格 → 起点吸附 → 标记 valid / invalid
4  按类别 R_c 剪枝候选 → 批量算路 → 降级兜底 → covered[]
5  计算 missing / level → 合并盲区块 → 裁剪到等时圈
6  渲染:盲区灰色层 + 非步行区域斜线层 + 设施点位
7  计算指标 → 生成文字结论 → 提供弹窗数据
```

## 7. 验收与测试用例

| 用例 | 预期 |
|---|---|
| 某格子周边 7 类设施均在各自 R_c 内步行可达 | level = 0,不绘制 |
| 某格子 7 类全缺 | level = 7,最深灰,仍能透出底图道路 |
| 直线距离近但被河或铁路隔断 | 判为缺失(真实可达生效) |
| 设施直线距离 > R_c | 不发起算路请求,判不可达 |
| 两个类别的 R 不同 | 各自按自己的 R_c 判定,互不影响 |
| 地铁站有 3 个出入口 | 计为 1 个设施,不重复计数 |
| 公交站不可达、地铁站可达 | 公共交通判为已覆盖 |
| 小区内名为"XX花园"的楼盘 | 不被当作公园 |
| 挂号处、食堂等子点 | 不单独计数 |
| 起点吸附距离大于 snap_max | 标记为非步行区域,用斜线纹理标示,不参与判定与指标分母 |
| 非步行区域与盲区块 | 互不重叠 |
| API 持续失败 | 触发降级并标记,系统不崩溃 |
| 盲区块越出等时圈 | 被裁剪到圈内 |
| 按类别筛选 | 只统计选中类别,重新着色 |

## 8. 风险与待确认

1. **各类别 R 的具体取值**:当前全部起始为 1000 m,是否按 3.1 的建议收紧(药店、购物、公园、公交站),取决于你的评判口径,需在技术文档中写明依据。
2. **封闭小区被判非步行区域的风险**:`origin.snap_max_m` 默认 150 m,需要在真实社区上实测,避免把居民区误标为非步行区域。
3. **斜线纹理的 SDK 支持**:实现前先验证所用 SDK 是否原生支持多边形纹理填充,否则需要走自定义图层或折线方案。
4. **7 级灰度的辨识度**:色阶需在实际底图上调试;若评审反馈难以区分,可同时调整灰度与透明度,但仍须保持透明灰、上限不超过 0.65。
5. **绕行系数 1.3** 为经验值,仅用于降级估算,应在文档中说明其局限。
